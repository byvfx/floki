# Floki voice

The tool speaks. The copy does not recruit the reader onto a team, and it does not narrate the people who built it.

## The line

Inspect, compare, and play multi-layer image sequences with color-accurate OCIO viewing.

Use that sentence for the README lede, the package description, the About dialog, the social card, and the desktop comment. Do not paraphrase it into a slogan.

## Posture

Floki is a viewer. Sentences name what it does and what the person operating it can do next.

* Name the object: the sequence, the layer, the pass, the cache, the display transform.
* Prefer the imperative in UI labels (`Open EXR…`, `Reset playback settings…`) and the indicative in docs (`Floki decodes the beauty layer while playback is moving`).
* Keep the technical noun. Say OCIO, AOV, exposure, frame, when that is the thing.

## Range

Brand lines say "image sequences." The application reads OpenEXR today, and technical docs should say EXR wherever they are describing that behavior: the file dialog, the header converter, a multi-part AOV. A brand sentence does not lock the product to one container format.

## Tone

Direct, specific, and short enough to scan. A feature gets the mechanism, not a compliment. "Byte-budgeted ring" is a description. "Blazingly fast" is not.

Numerals and units stay literal: `24 fps`, `0.10 / 0.20`, `#40A860`.

## Words to skip

* First person plural. The subject is Floki or the control, not a team.
* Hype adjectives standing in for a measurement.
* Pet names for the mark (no "the good boy," no gold, no foundry-yellow).
* "We support OpenEXR only" as a positioning line.

## Examples

About dialog, in full: the mark, `FLOKI · BYVFX`, the version, the line above, `MIT`, and links to the repository, the releases, and the docs.

A download heading names the binary and the platform. It does not welcome the reader.

A color note in the docs states the hex and what it is for. It does not ask the viewport to wear the brand.
